## 这次改变了什么

新增 `requests.py`，把“登记 → 发送 → 等待 → 终止”收敛为一套生命周期：

- `PendingRequest`：一次终态（`resolve` / `fail` / `cancel`），未读取异常会被标记为已取回。
- `RequestTable`：按连接、按类别（`addon.bridge` / `command.native`）分区；重复、未知、迟到
  回复返回 `False`，不会复活已结束请求；`close()` 幂等并失败全部挂起项。
- `AddonBridgeSession` 改为复用该表；`create_request` 在编码/发送之前登记，保持原
  `request_id` / `future` 兼容视图。
- 新增 `gateway/commands.py::NativeCommandClient`：`await client.run(command)` 发送原生命令并
  等待 `commandResponse`；`before_send` 完成登记，因此“发送过程中立即回包”不会丢。
- `ConnectionState.command_client` 由 facade 为每条连接安装；可靠模式与旧模式都可用。
- `server_facade._handle_raw` 在调用宿主钩子前完成命令回复配对；`error` 帧会把匹配的命令请求
  以 `RemoteCallError` 结束。
- `examples/addon-server` 删除 `WsCommandRunner` 等待表，改用 `state.command_client.run()`。

超时约定（公开说明）：超时只覆盖“帧被发送路径接受之后的远端等待”。发送排队失败由
`SendQueueFullError` 立即报告，发送/编码失败直接传播，不计入超时。

## 复核修复（2026-10-31）

复核发现三个边界问题，均在 `1997eed` 修复，并保留原异常与旧构造合同：

1. **编码失败残留（R02-4）**：`request_capability` 先登记请求，再在
   `try/finally` 之外执行 `encode_bridge_request` 与 `json.dumps`。当
   `payload={"invalid": {1}}` 抛出 `TypeError` 时，`pending_count` 保持 1，
   反复失败会耗尽额度。现在登记后的编码、日志准备、发送、等待全部放在同一个
   `try/finally` 中；失败释放条目并原样抛出原异常。回归
   `test_encoding_failure_after_registration_leaves_no_pending_request` 在旧实现
   失败，修复后连续 5 次失败仍无残留（配置上限为 2）。
2. **重复 id 覆盖（R02-3）**：同一 category 下重复 `request_id` 会覆盖旧条目并递增
   计数；两次登记后 `close()` 只完成第二个 future，第一个悬空。`reserve()` 现在
   抛出 `RequestDuplicateError` 且不触碰旧条目；`cancel(entry)` 按对象身份删除，
   旧条目无法误删后来复用同 id 的新条目。回归
   `test_duplicate_id_is_rejected_without_losing_the_first_entry` 与
   `test_stale_entry_cancel_does_not_remove_reused_id` 均在旧实现失败。
3. **旧构造合同（P2 兼容）**：`PendingAddonRequest` 曾改成仅接收 `entry` 的 frozen
   dataclass，旧的 `(request_id, capability, payload, future)` 直接构造与属性赋值
   都会失败。现在同时支持旧四参数构造（含关键字）和内部 entry 视图，属性可赋值；
   `test_pending_addon_request_keeps_legacy_constructor_and_assignment` 与
   `test_pending_addon_request_entry_view_and_keyword_constructor` 在旧实现失败。

公开 API 新增 `RequestDuplicateError`（`RequestError`/`ValueError` 子类），
`tests/unit/test_public_api.py` 快照已同步；既有导入、返回值与旧回调合同未改。
未修改线格式。MCBE 实机仍未验证。
