## 行为

正常完成保留待消费项，失败／取消清空缓冲，终止结果确定一次。
接收方取消会停止生产者后续发送并关闭迭代器；超载以 LIMIT_EXCEEDED 终止。
每流数量／字节与每连接合计字节有硬上限；定时器、生产任务、控制发送与墓碑有界。
断连等待 Python 生产任务退出；JavaScript 通过协作取消结束可解除的等待。
已交给传输层的帧与已经执行的世界修改无法撤回，不自动重放。
详细预算与超时合同见[协议文档](../../../protocol-v2.zh.md)。

## Review 与修复

独立 reviewer 发现 Python 超载拒绝流编号未保留墓碑，以及生产者嵌套调用没有继承 trace。
前者可能在拒绝后重放 open 执行生产者；后者造成跨调用追踪丢失。
最后一轮另修复 open 发送在 endpoint 关闭时未取消的问题，新增四项开流生命周期回归。
独立 reviewer 复测四项通过。以上问题均按失败回归复现后修复，最终复核与完整命令结果记于[第四阶段验收](phase4-final.zh.md)。

## 兼容、限制与回退

不支持流式的旧端明确报能力不支持。取消不影响同连接其他正常请求和流。
未完成传输分片受原 R11 TTL／配额管理，逻辑流结束后不交付迟到项；断连清连接池。
任意永不完成的 JavaScript Promise 不能被强制释放，生产者须响应 context.cancellation；
Python 生产者须允许任务取消。缓冲超限是显式结束，不是接收方额度背压。
R16 决定本轮是否增加额度；实机、版本矩阵与分发检查留 R18。
回退可禁用 stream/1，或仅撤回本阶段修改。
