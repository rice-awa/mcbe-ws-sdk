# V2-only 与 addon 冒烟整改方案

制定日期：2026-11-01。依据：[冒烟审查](../../reviews/2026-11-01-addon-smoke-test-review.md)及用户本次决定。
本文是待实现合同，不代表已完成。当前仅编辑文档，不修改源码、测试、依赖或 manifest，不安装、构建、提交或发布。
实施状态统一在[任务清单](tasks.zh.md)，本文不维护重复进度。

## 1. 已确定的边界

| 项目 | 最终要求 |
| --- | --- |
| 线协议 | 生产路径仅 MCBEWS/2；删除 MCBEWS/1 兼容回退和业务入口 |
| 旧客户端 | 服务端记录明确拒绝原因并关闭；不继续执行业务 |
| Script API | @minecraft/server 精确 2.8.0，@minecraft/server-ui 精确 2.1.0，与当前 manifest 一致 |
| 游戏基线 | 官方 1.26.30 发布说明提供上述 API；以此为目标核对最低引擎和 gametest，实机通过后才能声明支持 |
| 其他版本 | SDK/npm 项目、pack header、线协议版本分别管理，不全部改成 2.8.0 |
| 聊天入口 | 示例仅处理去掉首尾空白后以 ASCII `!` 开始的玩家消息 |
| 默认能力 | 两个只读快照默认可用；完整演示明确安装回声、流和受限制的世界命令 |
| 可靠性 | 保留独立读取、回复配对、玩家顺序、有限队列、字节预算和关闭清理 |

本决定覆盖旧方案中“保留旧 API/协议”“超时回退 V1”“无 addon 仍允许新默认服务处理业务”的最终要求。
R00—R17 记录保留为历史证据，不回写成当时已实施 V2-only。

## 2. 强制准入合同

```text
WS_TRANSPORT_CONNECTED → NEGOTIATING → READY_V2 → CLOSING → CLOSED
                              └────→ REJECTED ────→ CLOSED
```

- WS 建立不等于 addon 就绪。先启动读取、必要事件订阅与有界协商；不能在开始读取前 await 协商。
- NEGOTIATING 只处理协商、必要控制和关联的原生命令确认；不执行业务、不积压到准入后重放。
- 当前 attempt/epoch 确认成功后才发布业务 CONNECTED、调用 on_connected、发送成功欢迎。
- 未到 READY 的连接没有业务 CONNECTED，也不产生无配对的业务 DISCONNECTED；传输关闭与拒绝仍有独立诊断。
- READY 后混入旧业务帧也拒绝并关闭，不允许双协议并存。
- 超时、失败、提前关闭及 READY/关闭竞争只能得到一个终态；挑战、租约、请求、队列、任务、分片全部清理。
- V2 会话失效时撤销准入并关闭；重连获得新 epoch，不恢复旧会话或重放世界修改。

| 情况 | 行为 | 业务副作用 |
| --- | --- | --- |
| 合法 V2 握手 | 准入，记录版本、功能与会话 | READY 后可执行 |
| 明确旧版本或旧业务帧 | 记录 UNSUPPORTED_PROTOCOL 并关闭 | 0 |
| 无 addon / 无回复 | 限时记录 NEGOTIATION_TIMEOUT 并关闭；不能谎称已识别旧版本 | 0 |
| 畸形协商、不支持版本、busy、确认超时 | 区分原因并终止，无无限重试 | 0 |
| READY 前业务 | 丢弃并作有界摘要，不缓冲执行 | 0 |
| 错误来源、旧 attempt/epoch | 不用于准入或恢复请求；按归属拒绝/丢弃，不让无关来源取消合法会话 | 0 |
| 旧 Python 服务＋新 addon | 不分发旧请求、不返回旧成功响应；addon 记录拒绝 | 0 |

表中原因是诊断标识；如进入线错误码，须同步权威清单及双端测试。
游戏内升级提示可以限时尽力投递，但失败不能阻止服务端关闭。关闭码、原因长度和日志字段需固定并验证。
旧 Python 服务由外部程序持有 WS；addon 无关闭句柄时只承诺拒绝其旧业务，不虚称能强制断开旧服务。
新公开服务不提供绕过强制准入的兼容开关；审计旧 facade、`negotiate=False`、手动 activate 和注入对象，测试夹具不能成为生产绕过入口。
原生 MCBE `header.version=1`、`body.version` 保持原生合同，不能用来识别 MCBEWS/1 客户端。

## 3. V1 删除清单

| 层 | 现有位置 | 要求 |
| --- | --- | --- |
| 协商 | v2 runtime、manifest、生成资产 | 删除 V1 selection、_legacy、legacy_request、v1_methods 与回退描述 |
| 接入 | server、facade、hook、config | 移除默认旧服务与旧分支；复用可靠机制，落实准入 |
| 旧 API | 根导出、addon、profiles/mcbews_v1、extensions/mcbews_v1、Legacy 适配器 | 列出调用方及替代/删除决定；移除旧包路径和别名，不用 shim 留接口 |
| 共用配置 | config 等 | 中性 461 B 预算不再从 V1 清单导入，保留只能降低规则 |
| addon 路由 | router、bootstrap、main、toolPlayer | 删除旧 parser/request/sender 和旧业务排队；移除旧文本响应自动订阅、聚合兼容入口 |
| addon 扩展 | protocol/constants/chunking、responseSync、extensions/textResponse | 将仍需的 UTF-8/安全常量迁入中性模块；旧业务协议不进入生产包 |
| UI/session/approval/text | 旧 DTO、hooks、codec/delivery | 每项记录调用方和去向；仍需要的业务经通用 V2 交给宿主扩展，不重建 SDK 自有宿主业务 |
| 测试/工具 | fixture、生成脚本、名称检查、installed probe | 生产合同改为 V2；最小旧帧只用于拒绝测试，不保留正向 V1 服务能力 |
| 分发/文档 | pyproject、check_dist、CI、README、参考、AGENTS | wheel/sdist/addon 无 V1 实现；门槛不再强制旧资源；最终公开指南只用新入口 |

删除前建立“符号/路由 → 调用方 → 替代或删除 → 验收节点”清单，先迁移共用依赖再移除目录。
不要求全仓库 v1 字符串归零：历史文档、负向样本、原生协议和其他功能版本不应误删。
拒绝识别无需旧业务解码器、等待表、成功响应或兼容别名。

## 4. 依赖升级与产物

1. 对齐 package.json、lockfile、干净安装的模块和类型：server 2.8.0、server-ui 2.1.0；禁止回退现有 manifest。
2. 核对 gametest beta 开发类型、运行模块与目标引擎；不能将 gametest 也盲改为 2.8.0。当前世界启用步骤仍须注明 **实验 → 测试版 API（Beta APIs）**。
3. 官方 1.26.30 更新说明已明确两个目标 API。以该游戏基线核对并在实施时更新行为包/资源包最低引擎要求；具体 manifest 三元组与 gametest 组合须实机加载验证，不把旧 [1,21,80] 作为新版支持承诺。
4. 新类型下修正实际 API 差异，不能用 any、跳过测试或旧 node_modules 隐藏不兼容。
5. 同时检查跨文件一致性和批准目标值；仅比较 manifest/package 相等，无法发现一起误降级。
6. 读取最终 mcaddon 内 manifest 和 bundle，记录 SHA-256、能力配置、提交；重新导入后确认游戏实际加载产物。

官方来源及证据边界见[审查资料](../../reviews/2026-11-01-addon-smoke-test-review.md#6-资料与实施入口)。API 发布对应关系不是本项目实机通过证据。

## 5. 示例命令合同

前缀过滤只影响示例玩家命令分发与自动回复；不能影响通用事件订阅和协议内部消息。

| 输入 | 预期 |
| --- | --- |
| 空串、空白、a、stream 5、help、帮助 | 静默；0 回复、0 命令/能力/流调用 |
| hello !player、全角 ！player | 静默，不识别为前缀 |
| ` !player `、!inv、!cmd say hi、!wscmd say hi | trim 后按现有语义处理 |
| !help、!帮助 | 帮助正常；裸帮助别名移为带前缀别名 |
| !unknown | 一次未知命令提示 |
| 裸 ! | 一次用法提示，不执行命令 |
| 协商、MCBEWS2、commandResponse/error | 正常经 SDK 内部路径，不受前缀过滤 |
| 外部 tellraw 回声 | 保留分类，不触发回复循环 |

保留带前缀中文别名和已有大小写规则。同步检查其他聊天命令示例，但不强制 SDK 所有宿主只接收 !。

### 能力、错误与帮助

- 基础包默认两个快照；完整演示明确注册 demo.echo、demo.ticks、受限 run_world_command，安装和构建可重复。
- 示例与测试使用同一注册源；不能只在测试偷偷补能力。默认不开放世界命令，演示显式启用后仍保留 say 允许列表和禁止列表；验收成功与拒绝两条路径。
- 双端保留明确的机器码和可公开说明；message 不超过 256 UTF-8 字节、不截坏 Unicode。处理器内部异常保持脱敏。
- 服务端诊断保留 request/trace ID；玩家收到方法、错误码及行动提示，不直接拼内部 ID 或堆栈。
- 普通请求和流错误表现一致；移除仅适用 V1 的错误处理假设。
- 帮助优先按完整行和命令 token 分片；超长行安全回退，中文、emoji、长目标、标点和文件名回归，重组不丢字且每条命令不超预算。
- 传输来源、模拟玩家名和 metadata 不代替宿主身份授权。

## 6. 诊断

记录传输建立、协商开始、V2 就绪、拒绝/超时、会话失效、关闭及清理摘要；包括连接标识、协议、功能、原因和必要关联字段。
完整 payload 默认关闭，显式 --log-raw 开启；--no-log-raw 行为一致并注明脱敏边界。
记录能获得的 close code/reason 与发起方，无法获知时标 unknown。
零字节 EOF 来源未证实：先补诊断，有证据后才精确降级预期噪音，不能屏蔽全部 websockets 错误。

## 8. 最低验收矩阵

| 编号 | 场景 | 判据 |
| --- | --- | --- |
| A01 | 新服务＋新 addon | V2 READY 一次；请求/通知/流正常 |
| A02 | 新服务＋旧 addon | 明确拒绝或无回复超时关闭，无成功欢迎与业务副作用 |
| A03 | 旧服务＋新 addon | 不执行旧请求、无旧成功响应；记录拒绝，明确 addon 不能直接关 WS 的边界 |
| A04 | 新服务＋无 addon | 限时关闭；不回退或继续执行 !wscmd |
| A05 | 早到业务、迟到 ready、伪造/过期 epoch、混入旧帧 | 不能绕过准入或恢复终态，无重放 |
| A06 | 关闭与超时/确认/回复竞争、租约失效 | 结果一次；等待、任务、队列、租约、分片清零 |
| A07 | 前缀输入表 | 无前缀零回复零调用；带前缀正常，协议不受影响 |
| A08 | 基础/演示包与错误 | 未注册、参数错误、处理器失败可区分；演示命令完整可运行 |
| A09 | 帮助、中文/emoji/长目标、460/461/462 B raw 命令 | 可容纳 token 不劈开；预算内完整发送、超限 raw 明确拒绝 |
| A10 | 双向大项、首段、结束、取消、慢端、重连 | 实际持续交付、有界、不串流；取消后其他请求正常 |
| A11 | 两玩家、同玩家 FIFO、回声 | 归属正确，无互相阻塞或回复循环 |
| A12 | 新依赖与安装分发 | 干净安装目标版本；类型/测试/构建通过；包内无 V1 实现、仓库外旧路径导入失败 |
| A13 | 日志 | 接受/拒绝和关闭原因可判断；默认无全量 payload，诊断故障不影响收发 |

沿用 Python 3.11—3.14、websockets 12/14/16、85% 覆盖率及既有质量门槛。
协议检查切换到 V2 权威资产，旧工具删除/重构同步修改 CI 和验证命令，不能仅删除门槛。
