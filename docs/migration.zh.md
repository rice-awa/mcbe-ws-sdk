# 迁移到受管理的服务入口

本文描述**尚未发布的当前源码**。PyPI `0.2.1` 不包含 `McbeServer`，
也不包含本轮新增的 v2 与流式接口。运行这些示例请在当前仓库执行
`pip install -e ".[dev,docs]"`。仅凭包内版本号不能判断本轮改动已经发布。

## 选择入口

| 合同 | `McbeServerFacade()` | `McbeServer()` |
| --- | --- | --- |
| 默认调度 | `legacy`，读取循环逐个等待回调 | `reliable`，SDK 管理有界业务任务 |
| 聊天顺序 | 一条连接逐个等待回调结束 | 同一玩家先进先出，不同玩家可并发推进 |
| 在聊天钩子中等待回复 | 会堵住负责接收该回复的读取循环 | 可直接等待命令或能力调用 |
| 连接回调 | 等待 `on_connected` 结束后才读取业务帧 | 先完成握手与订阅；`on_connected` 与玩家队列分开管理，不能假定它先于聊天钩子结束 |
| 事件观察与钩子 | 内联事件投递结束后才调用对应钩子 | 观察与业务使用不同队列，不保证全局完成顺序 |
| 回复关联 | SDK 先关联已登记回复，再调用响应钩子 | 保持关联优先，等待者不依赖响应钩子结束 |
| 钩子返回值 | `None`；`parsed` 是注册表匹配结果，不是“已消费”标记 | 保持相同签名和返回约定 |
| 命令返回值 | `NativeCommandClient.run()` 返回 `MinecraftCommandResponse` | 相同的类型化命令响应 |
| 能力返回值 | v1 客户端返回能力结果字典 | 协商调用返回协议响应信封，读取 `result`，v2 远端错误抛出 `RemoteCallError` |
| 默认设置 | 原有设置、中性响应接收器、v1 桥接 | 可靠调度并探测 v2；其余安全预算仍有上限 |
| 原生事件 | 需要显式启用可靠调度 | 通过 `state.native_events` 使用 |
| 必需元数据与流式 | v1 不提供 | 必须协商到兼容能力，失败时不会丢弃字段降级 |

需要保持原回调顺序时继续使用旧构造器。现有 `McbeServerFacade` 宿主也可用
`GatewaySettings(dispatch=DispatchSettings(mode="reliable"))` 显式启用可靠调度；
接入 v2 还需要 `V2Bridge`。新入口为新宿主组装这条路径。即使注入设置指定旧模式，新入口也会将
`dispatch.mode` 设为 `"reliable"`，保留其他显式设置。
具体用法见[快速开始](getting-started.md)与可运行示例。

只有旧串行路径在钩子中等待同一连接的回复时，才需要宿主自行启动后台任务来避开阻塞。
新入口由 SDK 管理任务，示例不要求宿主维护请求编号等待表或分片缓存。

## 失败、取消与关闭

原生命令可能返回非零 `statusCode`，需要检查类型化响应。
v2 远端错误抛出 `RemoteCallError`；传输故障、超时、协商不支持也会抛出异常。
v1 回退仍在 `result` 中保留能力级失败，需要检查其 `ok` 字段；
都不能当作成功。未知方法、输入不合法和处理器异常有明确协议错误。
通知没有回复，也不创建回复等待项。

取消等待中的调用会放弃该调用。断连会使未完成请求失败，并关闭受管理任务。
`await server.stop()` 停止服务；取消 `run_lifetime()` 也会触发清理。
取消无法撤回已经交给传输层的帧，也不撤销已经执行的世界修改。
重连建立新会话，不自动重放请求或世界命令。

调度器隔离回调异常，超载时明确拒绝，不无限积压。同步回调必须简短且不阻塞。
同一玩家的后续回调仍要等待前一条完成；不要递归等待排在当前顺序组后面的业务。
v2 处理器不能重入正在执行的方法顺序组，此类调用会被明确拒绝。

## 协商与回退

探测有截止时间。旧附加包或没有探测回复时，仅为已知兼容方法选择 v1；
普通聊天和原生命令独立运行。不支持的版本或未完成确认会明确失败。
必需元数据和 `stream/1` 不会降级成丢字段的 v1 调用，也不会先缓存完整响应再冒充持续流。

需要保留旧路径时，用原有设置和附加包构造 `McbeServerFacade`，并保留配套附加包资产。
重新连接以建立新会话，不通过重放副作用来“回退”。本轮没有改变旧默认值，没有发版，
也没有扩大 Minecraft 平台或版本支持承诺；实机兼容仍需单独验收。
